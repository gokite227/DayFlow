# DayFlow Mobile

Expo SDK 57 + React Native 0.86 + Expo Router. Uses the same Spring API and generated client
(`@dayflow/api-client`) as the Web. The target is a **Development Build** (the iOS Screen Time module
planned next needs its own native project). Everything implemented so far — screens, Calendar gestures
(react-native-gesture-handler + Reanimated), settings, theme and local notifications — uses only modules
that ship with Expo Go, so it can also be tried in Expo Go on a phone.

## Navigation and settings

- Bottom tabs: four configurable slots + **Settings** (always last). Default: Today / Days / Calendar /
  Events / Settings. Settings → 하단 탭 설정 picks and orders the four slots (Today, Days, Calendar, Events,
  Goals, Review, Recovery; no duplicates; reset to defaults). Screens that are not tabs open from
  Settings → 기능 바로가기 (or links) as stacked screens with a back button. Event detail and other
  detail routes work regardless of the tab setup (notification deep links included).
- Settings → 화면 모드: 시스템 설정 / 라이트 / 다크 (light and dark palettes in `@dayflow/design-tokens`).
- Settings → 한 주 시작 요일: 월요일 / 일요일, **Calendar display only**. Goal WEEK periods stay the
  canonical Monday-start weeks of the server, and Review weeks keep their Monday rule.
- Settings are device-local (AsyncStorage key `dayflow.settings.v1`, `src/features/settings/`); broken or
  old values fall back to defaults field by field.

## Calendar

- Views: 하루 (default) / 3일 / 주. The week view scrolls horizontally instead of squeezing seven columns.
- Top row: all-day Events (Category-colored bars) and date-only Days. Below: 00:00–24:00 grid, hour and
  half-hour lines, current-time line, first open scrolls near now; 오늘 returns to today and now.
- Day: **long press (~0.3 s) and drag** to another time, another date column, the top row (date only), or
  onto the `날짜 없음 N` button (clears the date). Drag the **bottom handle** to resize. 15-minute snap,
  15-minute minimum. Drops use the existing Day / schedule API once, with an optimistic update that is
  rolled back on error. Day edit also has `날짜 없음으로 이동`.
- `날짜 없음 N` opens the right drawer of Days without a date; long press a Day there and drag it onto the
  grid (length = estimate rounded to 15 minutes) or a date column. Close with ✕, tapping outside, or a
  swipe to the right.
- Events are shown and open on tap; they are never dragged or resized.
- Model and tests: `src/features/calendar/calendar-grid.ts` (overlap lanes come from
  `@dayflow/domain` `layoutOverlaps`, shared with the Web).

## 1. API base URL

```bash
cp apps/mobile/.env.example apps/mobile/.env.local
```

Set `EXPO_PUBLIC_DAYFLOW_API_BASE_URL` (no default; the app shows a setup screen when it is missing):

| Where the app runs | Value |
| --- | --- |
| Android emulator | `http://10.0.2.2:8080` |
| iOS simulator | `http://localhost:8080` |
| Physical device (same Wi-Fi) | `http://<computer LAN IP>:8080` |

On a phone `localhost` is the phone itself. The value is inlined when Metro starts, so restart
`start` after changing it. Debug Android builds allow plain HTTP; iOS does not apply ATS to IP addresses.

## 2. Install and run

```bash
pnpm install
```

Create a development build once (and again after adding native modules or changing `app.config.ts`):

```bash
pnpm --filter @dayflow/mobile android
```

```bash
pnpm --filter @dayflow/mobile ios
```

- `android` needs Android Studio / SDK (an emulator or a USB device with debugging on).
- `ios` needs macOS + Xcode (simulator, or a device with a signing team). Cloud alternative:
  `eas build --profile development` (or `development-simulator`) with `eas.json`.

Then start Metro for the installed build (or, for the current Expo Go–compatible scope, `pnpm --filter @dayflow/mobile exec expo start` and scan the QR code in Expo Go):

```bash
pnpm --filter @dayflow/mobile start
```

Native folders (`android/`, `ios/`) are generated by `expo prebuild` and git-ignored (Continuous Native
Generation). Native changes go through `app.config.ts` plugins, not edits to generated folders.

Tests cover pure TypeScript helpers with Vitest (same runner as the rest of the monorepo). There is no
React Native component test runner yet; screens are covered by typecheck, lint and the Metro bundle check.

`expo`, `expo-notifications` and `typescript` are listed in `expo.install.exclude`: the repository's
pnpm `minimumReleaseAge` policy holds back patch releases younger than a day, and the monorepo stays on
TypeScript 5.9 for now.

## 4. Event reminders (local notifications)

- Reminders are scheduled on the device from `GET /api/v1/events` (offsets) and
  `GET /api/v1/event-occurrences` (computed occurrences). No push server is involved.
- Timed Event: occurrence start − offset. All-day Event: 09:00 of the occurrence date in the Event
  timezone − offset (wall clock, so "1일 전" stays the previous day 09:00 across DST).
- Rolling window of 30 days, at most 48 pending reminders (iOS allows 64 per app; the rest is kept for
  future Day nudges). Reconcile runs on app start, when the app returns to the foreground (at most once a
  minute), after an Event create/update/delete succeeds on the server, and after permission is granted.
- Code: `src/features/notifications/` — `reminder-plan.ts` and `reconcile-plan.ts` are pure and tested;
  `notification-adapter.ts` is the only module that calls expo-notifications / AsyncStorage.
- Android channel: `dayflow-events` ("DayFlow Events", default importance).

### Manual test on a device

1. Settings → 알림 → 일정 알림: the state is 미결정; tap 알림 허용하기 and allow.
2. Create an Event starting 3 minutes from now with reminder 정각 (and 10분 전 for a later one).
3. Settings → 알림 예약 상태 (개발 빌드): the reminder is listed with its trigger time.
4. Wait for the notification; tap it → the Event detail opens.
5. Edit the Event time → the debug list shows the new trigger only; the old one never fires.
6. Remove the reminder → the list is empty. Add it again, then delete the Event → the list is empty.
7. Create a weekly Event with a reminder → one pending notification per week inside 30 days.
8. Create an all-day Event tomorrow with 1일 전 → trigger today 09:00 (or none if already past).
9. Force-quit and reopen the app, or change the Event on the Web and return to the app → the list
   matches the server again.
10. Deny the permission in the OS settings → Settings → 알림 shows 거부됨 with 설정 열기.
